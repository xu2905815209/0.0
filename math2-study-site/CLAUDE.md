# CLAUDE.md — 数二精华课（项目总规则）

> **最高优先级：任何 AI 在开始本工程任务前，先完整阅读本文件，再阅读 PROJECT_STATE.md，然后检查将要修改的源码。**
> 本站的目标不是收集提问，而是帮助首次备考数学二的学生形成可迁移的解题能力。

## 1. 产品定位：精选考点库，不是聊天问题合集
- 用户在聊天中提出很多类型的问题：概念不懂、当下估分、某题辨认、对讲解追问、学习策略、网页功能建议。
- **不能默认“用户问了 = 网站必须新增一条”。** 无论用户问几次，都不代表要新增同等数量课程。
- 网站里只留值得长期重复学习的 **考研数学二高价值、可迁移的知识与解题方法**。
- 不公开照抄用户发来的口语问题、临时疑惑、图片截图说明或“这题多少分”等杂项。
- **不要把网站做成“全部问答记录”**。一次性事实、难度或赋分估计、生活/产品/技术类问题一般只在聊天回复。
- 网站内容不以收录条数作为成绩。专题数量少且精，比混杂大量小卡片更好。

## 2. 上架前必须依次通过四道筛选
1. **相关性**：直接关联数学二可考知识与常用解题能力，优先基础母题/高频思路/核心易错点。
2. **迁移价值**：适用于一类题，而不只是当前照片里某题的数值或某次提问。
3. **严谨正确**：题干清楚、推导完整、数学条件充分；图片模糊或条件未确认时，不强行出版成课程。
4. **教学质量**：可以讲清「题面信号 → 为什么想到 → 推导 → 易错点 → 主动回忆」。否则先在聊天中解释，不上架。

**只要有一关没通过，就不新增课程。** 旧课程中已经解释过的概念，优先融入原课程、改善表达，而不是创建重复卡片。

## 3. 一次请求的工作流
1. 阅读 CLAUDE.md。
2. 阅读 PROJECT_STATE.md。
3. 检查现有内容目录、目标课程、网站脚本与样式；避免重复或破坏互动。
4. 将用户请求分类：
   - A. 一次性问答：聊天回答，不改变站点。
   - B. 已有主题追问：若有新的可迁移内容，则**修改原专题**，不新建条目。
   - C. 全新核心考点：通过四关后，作为一个**概念化的精选专题**加入。
   - D. 纠错或体验问题：只修复对应内容/功能，不增加学习专题。
5. 整理到考场语言，删去聊天元数据、临时口吻、个人情绪、未经核实的赋分猜测。
6. 必须正确使用数学表达、检查逻辑、检查已有进度存储键不变。
7. 更新内容与 PROJECT_STATE.md，推送仓库；检查部署工作流成功后才宣称“已上线”。

## 4. 课程怎么讲
每篇课程应该是独立的教学专题，标题为可检索的**知识或方法名**，不是原封不动引用学生问题。
- 开头：看到什么题面信号？为什么想到这个办法？
- 主线：先一个小例子/图像直觉，再完整推导，关键变形不能跳。
- 公式：尽量用 **MathML 真正竖式分数**，不要在公式区域用斜杠 / 代替分数线。
- 对比：需要区分的相近知识，明确写出适用条件和区别。
- 易错：点态/邻域、必要/充分、带符号面积、内外层链式求导等不能偷换。
- 练习：至少一个可操作的主动回忆题，优先检查选法而不仅是结果。
- 数形结合或可交互说明**确实能帮助理解**时再加入，不做无意义交互。
- 文本简明；讲透难处，但不能堆砌无关拓展或不必要的考试难度判断。

## 5. 当前网站结构
- \`index.html\`：精选主题首页、掌握状态与复习区，非教学全文。
- \`assets/styles.css\`：样式。
- \`assets/site.js\`：目录加载、导航、复习互动、浏览器状态。
- \`content/catalog.json\`：唯一公开目录，**只列精选课程**。
- \`content/k001.html\`：导数图像与原函数增量。
- \`content/k002.html\`：分式函数的 n 阶导数。
- \`PROJECT_STATE.md\`：当前上架情况和下一步任务。

课程以 **K001、K002…** 编号表示经过筛选的专题，不再按聊天问题自动递增 Q 序号。新问题不一定导致新编号。元数据、全文和交互不得相互矛盾。
